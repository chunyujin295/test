### 2.2 Job/Task 两级结构

传统任务的关键区别：**一个 Job 包含多个 SubTask**。

```

Job (J_Block_xxx.bin)
  ├─ tasksmap:
  │   ├─ task[0]: GenTasks (ATSTARTTYPE)      → 拆分出 task[1]..task[N]
  │   ├─ task[1]: 空三/SfM                     → 子进程执行
  │   ├─ task[2]: 重建/MVS                      → 子进程执行
  │   ├─ task[3]: 生产/Texturing                → 子进程执行
  │   └─ task[N]: ATLASTTASKTYPE               → 收尾 task
  └─ feedback: JobFeedBack_s
```

- **Task 级完成**：单个子进程返回 `MOLDAI_SUCCESS` → 该 task 标记完成，但 job 仍在 Running/
- **Job 级终态**：所有 task 完成 / 任一 task 取消/失败 → job 移动到 Completed/Cancelled/Failed/

**结算应该在 Job 级终态触发**，不是每次 task 完成都触发。

### 2.3 `ExecTaskFileV2()` 三种入口

函数根据 `type`（task 的类型）分三种情况：

| type                    | 含义                    | 子进程？ | 触发时机                             |
| ----------------------- | ----------------------- | -------- | ------------------------------------ |
| `ATLASTTASKTYPE`        | job 的最后一个收尾 task | 否       | tasksmap 中其他 task 都已完成后      |
| `ATCOMPLETETYPE`        | 标记 task 完成          | 否       | 与 ATLASTTASKTYPE 类似，但不移动 job |
| 其他 (空三/重建/生产等) | 实际算法 task           | 是       | Engine pick up 此 task 时            |

## 三、生产任务的特殊处理 —— 哨兵文件 + 分布式安全

### 3.1 目录结构

从 `CreateProductionJobFiles`（line 1406）可以看到生产目录布局：

```
projectdir/
  Block_N/
    Reconstruction_M/
      Productions/
        Production_P/
          merge.lock                    ← 已存在的锁文件
          Tile_000/                     ← productiontile_dir (= blockItem_)
            J_<ts>_TILE_0_<proj>_BxRxPx_<name>/  ← task 工作目录
            JF_<jobname>.bin            ← tile feedback
          Tile_001/
            JF_<jobname>.bin
          Tile_002/
            ...
```

每个 Tile 目录在 `CreateProductionJobFiles` 中已预创建（`File::MakeDirEmpty`）。

从 Engine 视角（`ExecTaskFileV2`）：
- `atparam.projectFile_` → 项目路径（含 Block）
- `atparam.blockItem_` → `Block_N/Reconstruction_M/Productions/Production_P/Tile_XXX`
- Tile 目录 = `projectdir + "/" + blockItem_ + "/"`
- **Production 目录** = Tile 目录的父目录
- **Tile 总数** = Production 目录下 `Tile_*` 子目录数量（预创建，稳定）

### 3.2 哨兵文件方案

核心思路：**每个 Tile Job 到达终态时，在 Production 目录下写一个哨兵文件。当哨兵数量 == Tile 目录数量时，说明所有 Tile 都已终态，触发 Production 级结算。**

这不是通过扫描 Job 目录来判断"还有没有剩余"，而是在 Production 自身的目录结构中计数——更直接、更可靠。

```

一个 Tile Job 到达终态（Completed / Failed / Cancelled）
  │
  ├─ 1. 现有逻辑：保存 job 到终态目录，删除 Running/ 中的 job
  │
  ├─ 2. ★ 写哨兵文件:
  │      productionDir/sentinels/<tilename>.done
  │
  ├─ 3. ★ 统计：
  │      列出 productionDir/Tile_*/ 子目录 → tile 总数
  │      列出 productionDir/sentinels/*.done → 已完成 tile 数
  │
  ├─ 4. ★ 如果哨兵数 >= tile 目录数 → 所有 Tile 已终态:
  │      ├─ Lock (sentinelDir/settle.lock)
  │      ├─ 二次确认
  │      ├─ 遍历每个 Tile_XXX/JF_<jobname>.bin
  │      │    → 读取 feedback.Status
  │      │    → 统计: completed / failed / cancelled 各多少
  │      ├─ 执行 Production 级结算
  │      └─ 写 settled.done 防止重复结算
  │
  └─ 5. 如果哨兵数 < tile 总数 → 还有其他 Tile 在跑 → 不结算
```

```cpp
// 三个终态分支 (COMPLETED/CANCELED/FAILED) 在各自 jobinfo.save 之后调用
// imageCount: 调用方从 Block 获取 (Block 在共享存储上, 任何节点都能读到)
static void OnTileJobFinished(const std::string& jobname,
                               const std::string& projectFile,
                               const std::string& blockItem,
                               int imageCount)
{
    // 只处理 Tile Job
    if (jobname.find("_TILE_") == std::string::npos)
        return;

    // projectFile  = atparam.projectFile_  (如 "D:/project/project.moldai")
    // blockItem    = atparam.blockItem_    (如 "Block_1/Recon_1/Productions/Prod_2/Tile_000")
    std::string projectDir   = AICORE::File::GetParentDir(projectFile);
    std::string tilePath     = projectDir + "/" + blockItem;
    std::string productionDir = AICORE::File::GetParentDir(tilePath);

    // 1. 写哨兵文件
    std::string sentinelDir = productionDir + "/sentinels/";
    AICORE::File::CreateDirIfNotExists(sentinelDir, true);
    std::string tileName = AICORE::File::GetFileName(blockItem);  // "Tile_000"
    {
        std::ofstream ofs = AICORE::File::OpenOfstreamUtf8(
            sentinelDir + tileName + ".done", std::ios::out);
        // 空文件即可, 哨兵只是标记
    }

    // 2. 数 tile 总数
    int totalTiles = 0;
    {
        auto dirs = AICORE::File::GetDirList(productionDir);
        for (auto& d : dirs) {
            if (d.find("Tile_") != std::string::npos)
                totalTiles++;
        }
    }

    // 3. 数哨兵数
    int sentinelCount = 0;
    {
        auto files = AICORE::File::GetFileList(sentinelDir, "*.done");
        sentinelCount = (int)files.size();
    }

    // 4. 全部完成 → 结算
    if (sentinelCount >= totalTiles)
    {
        std::string settleLock = sentinelDir + "settle.lock";
        FILE* fp = AICORE::File::FopenDenyWriteLockUtf8(settleLock);
        if (fp != NULL)
        {
            // 二次确认
            auto files = AICORE::File::GetFileList(sentinelDir, "*.done");
            if ((int)files.size() >= totalTiles)
            {
                // 读取 freeze_no (提交时写入)
                std::string freeze_no = ReadEncryptedFile(
                    productionDir + "/freeze_no.bin");

                if (freeze_no.empty()) {
                    LOGE("freeze_no not found in " + productionDir);
                    fclose(fp);
                    return;
                }

                // 拼 task_param_json (imageCount 由参数传入, totalTiles 从目录数)
                std::string taskParamJson =
                    BuildTaskParamJson(imageCount, totalTiles);

                // 遍历每个 Tile 的 feedback 统计终态
                int completed = 0, failed = 0, cancelled = 0;
                {
                    auto tileDirs = AICORE::File::GetDirList(productionDir);
                    for (auto& td : tileDirs)
                    {
                        if (td.find("Tile_") == std::string::npos) continue;

                        std::string tilePath = productionDir + "/" + td + "/";
                        auto fbFiles = AICORE::File::GetFileList(tilePath, "JF_*.bin");
                        for (auto& fb : fbFiles)
                        {
                            JobFeedBack_s feedback;
                            if (feedback.load_with_retry(tilePath + fb, false))
                            {
                                switch (feedback.Status)
                                {
                                case jobsta_e::STATUS_COMPLETE: completed++; break;
                                case jobsta_e::STATUS_FAILURE:  failed++;    break;
                                case jobsta_e::STATUS_CANCLE:   cancelled++; break;
                                }
                            }
                            break;  // 每个 tile 只有一个 JF 文件
                        }
                    }
                }

                // 结算 — taskParamJson 与冻结时一致 (含 images + tiles)
                std::string settleStatus = (failed > 0 || cancelled > 0) ? "fail" : "success";
                auto settleResult = PointManager::SettlePoints(
                    freeze_no, settleStatus, taskParamJson);

                // 标记已结算 (幂等)
                {
                    std::ofstream done = AICORE::File::OpenOfstreamUtf8(
                        sentinelDir + "settled.done", std::ios::out);
                    done << "done";
                }
            }
            fclose(fp);
        }
    }
}
```

### 3.5 为什么这个方案分布式安全

| 维度 | 说明 |
|------|------|
| **信源** | Production 目录下的 Tile 子目录 + 哨兵文件，都在**共享存储**上，所有节点可见 |
| **Tile 总数** | 从磁盘目录结构直接数（`CreateProductionJobFiles` 预创建），不依赖任何节点内存 |
| **并发互斥** | `settle.lock` — 和现有 `.lock` 机制一致（`FopenDenyWriteLockUtf8`），只有一个节点能执行结算 |
| **二次确认** | 拿到锁后重新计数哨兵，防止 TOCTOU 竞态 |
| **幂等保护** | `settled.done` 标记 + `settle.lock` 双重保护，不会重复结算 |
| **终态收集** | 结算时遍历所有 Tile 的 feedback 文件，拿到的都是已持久化的终态数据 |

## 四、统一方案建议

### 方案 A：在 `ExecTaskFileV2` 中直接插入

在每个 `jobinfo.save(终态路径)` 之前插入结算调用。优点：与现有逻辑紧密耦合，能拿到所有上下文。缺点：改 `CallEngine.cpp` 的地方较多（4 个位置）。

### 方案 B：独立结算线程扫描终态目录

启动一个后台线程，周期性扫描 `Completed/`、`Failed/`、`Cancelled/` 目录：
- 遍历目录下的 job 文件
- 加载 job → 检查是否已结算（可在 job 中加 `settled` 标记）
- 未结算 → 执行结算 → 标记已结算

优点：不改 `ExecTaskFileV2`，逻辑独立，不会因结算失败影响任务流转。缺点：有延迟，需要额外的结算状态标记。

### 方案 C：在 `hasFinishedJobMap` 处统一回调

当前代码在终态设置后会写入 `hasFinishedJobMap`（值 2=完成, 3=取消, 4=失败）。可以在设置 `hasFinishedJobMap` 之后、`jobinfo.save` 之前，统一调用结算函数：

```cpp
// 在每个 hasFinishedJobMap.insert() 之后立即:
SettleJob(jobinfo, /* completed/cancelled/failed */);
```

这样可以在 `hasFinishedJobMap` 的 3 个终态设置处（line 2757, 3262, 3406, 3728）后统一处理。
