# 服务端接口安全

## 签名

签名是为了防止请求被仿冒篡改，需要对请求的内容进行加密，然后传输，一个请求通常包括

- 请求data信息

- 时间戳

- accessToken （只有登录接口有）

- sign签名

其中sign是对前三个内容总和进行加密得到的，需要客户端，服务端分别保留秘钥，客户端加密，服务端解密，

服务端收到数据需要对前三个算签名，验证签名是否一致，如不一致，说明被篡改

签名，accessToken，时间戳 的结果放到 header里

```Plain Text
//数据字段
var paramData ={};
if (httpMethod = "get"){
    paramData = getUrlParam();   //get请求对应的是url上的参数
}else if (httpMethod = "post"){
    paramData = getBodyParam();   //post请求对应的是body中的参数
}
//将数据obj按参数（也就是key）排序
dataSortedObj = sortedObjByKey(paramData);
//转为string
dataPartStr = JSON.stringify(dataSortedObj);

//请求的路径string， 即  http://XXX/path/to/api 格式的，去掉域名后的/path/to/api
urlPartStr = getReqURL();

//时间戳
timestampStr = getCurrentTime();

//accessToken, 该字段在有些接口中没有
accessTokenStr = getCurrentToken();

//盐
saltStr = "moldai";

//拼接原始字段
//按顺序 盐，路由，时间戳，数据，accessToken 拼接，中间用":"连接
//注意，如果某个部分不存在，比如没有data，或没有accessToken，则这些部分不参与拼接
finalStr = saltStr+":"+urlPartStr+":"+timestampStr+":"+dataPartStr+":"+accessTokenStr;

//计算hash得到sign
signStr = MD5(finalStr).toBase64();

//请求的时候写入header
//每对参数拼成 参数名：参数值，多个参数用“,”拼接
//header拼接也只拼接有值的部分，accessToken可能不参与拼接
setHeader("Authorization") = "accessToken:" + accessTokenStr+ ","
                             + "timestamp:" + timestampStr+ ","
                             + "sign:" + signStr ;
```

## token

除登录，注册外的接口都需要accessToken，

accessToken生成时机是登录并验证密码通过后生成，并返回给客户端，同时以账号为key存储在redis，

accessToken包含的信息包括：

- 账号

- 生成时间

- osid   操作系统信息

- mid   硬件信息

登录状态下，接口请求带上accessToken，并验证

- redis里是否有该accessToken

- 验证accessToken存储的信息是否正确

- accessToken对应的机器信息是否正确

然后可以获取accessToken对应的账号信息操作。

redis中的accessToken有有效期，需要定时刷新，否则过期则无效，表示登出

为了无感知，通常有两个token，正常的accessToken，有效期较短，另有一个refreshToken，有效期较长，

加上刷新逻辑

- 客户端发现accessToken失效后，使用refreshToken请求，获取新的accessToken

- 更新服务端和客户端的accessToken，但refreshToken视情况刷新

## 明文加密

对于账号的登录，密码明文需要加密，目前的方法是：

- 前端对密码加密 SHA\-256， CryptoJS 库

- 传输到后端，后端对密码二次加密**bcrypt**，加盐，盐是随机的，存储盐

- 验证时，收到前端加密后的密码H1, 然后查询本地账号对应的密码，和盐，加盐后得到H2，对比H1和H2是否一致

## 请求规范

- 网络请求带token，而不是用户信息，

- token定时失效

- 敏感信息加密

- 非对称加密保护好秘钥
