# 积分接口集成方案

## 〇、适用范围

本文档描述积分系统的统一接入方案，**同时适用于重建式任务和生成式任务**。

| 任务类型 | 调度方式 | 结算时机 | 涉及模块 |
|----------|---------|---------|---------|
| 生成式 (GenTask) | GenTaskThread 轮询 HTTP | QueryTaskStatus → COMPLETED/FAILED/CANCELED | GenHttpClient / GenTaskThread |
| 重建式 (Reconstruction) | Engine spawn Task.exe 子进程 | Task.exe 退出 → JobFeedBack_s 终态 | HttpClient / CallEngine / TaskProcess |

两者的积分 API（freeze/settle/outline/estimate）和核心原则（先结算再更新状态）是**完全相同**的，差异仅在于发起结算的调用点不同。

---

## 一、背景与问题

### 1.1 积分接口

后端已定义 4 个积分相关接口 (详见 `App/doc/积分接口.md`)：

| 接口 | URL | 用途 |
|------|-----|------|
| 查询积分 | `POST /point/outline` | 查用户总积分/冻结积分/可用积分 |
| 估算消耗 | `POST /point/estimate` | 任务提交前估算消耗 |
| 冻结积分 | `POST /point/freeze` | 创建任务时冻结积分，返回 `freeze_no` |
| 积分结算 | `POST /point/settle` | 任务完成时清算积分，扣除/返还 |

### 1.2 核心问题：结算丢失

```
时间线 (以生成式为例):
  1. API 轮询 → COMPLETED
  2. 更新 job.status=COMPLETED, 写 feedback, 更新 Block
  3. 移到 Completed/                         ← 进程在此刻崩溃
  4. 发送 /point/settle 请求                  ← 永远没发
  → 结果: 前端看到"完成"，但积分未被扣除
```

重建式同样存在此问题：Task.exe 执行完毕、Engine 更新 JobFeedBack_s 为 COMPLETE 之后到调用 settle 之间，进程可能退出。

**根因**：状态更新和积分结算不是原子的，现有代码先改状态再考虑积分。

### 1.3 解决方案

**原则：积分结算必须先于状态更新。**

```
终态到达 (COMPLETED / FAILED / CANCELLED)
  → 1. POST /point/settle (可重试)
      ├─ 成功 → 2. 更改 job 状态/结果/feedback/Block
      └─ 失败/超时 → 保持当前状态，下轮重试
```

增加 `points_settled` 标志位解决崩溃恢复：settle 成功后先置位并落盘，再更新状态。即使置位后崩溃，重启后进程看到 `points_settled=true`，跳过 settle 直接完成状态更新。

## 二、数据结构

> **归属文件**: `Include/Core/PointManager.h`。`PointFreezeInfo`、`PointSettleInfo`、`PointInfoBase` 均定义在此文件中，与 `PointManager` 类在同一头文件。`GenTaskProcess.h` / `TaskDef.h` 通过 `#include "Core/PointManager.h"` 获取 `PointInfoBase`。

### 2.1 PointFreezeInfo — 冻结积分返回结果

同时复用于 `/point/outline`（查询）和 `/point/estimate`（估算）的返回值——缺少的字段留默认值即可。

```cpp
/// @brief 积分冻结/查询/估算共用返回结构
///        /point/freeze  → freeze_no / total_balance / frozen_points / available_points
///        /point/outline → total_balance / frozen_points / available_points (freeze_no 为空)
///        /point/estimate → estimate_points / total_balance / frozen_points / available_points
struct PointFreezeInfo {
    std::string freeze_no;          // 冻结单号 (仅 /point/freeze 有值)
    int estimate_points = 0;        // 预估消耗 (仅 /point/estimate 有值)
    int total_balance = 0;          // 总积分
    int frozen_points = 0;          // 冻结积分总额
    int available_points = 0;       // 可用积分
};
```

### 2.2 PointSettleInfo — 结算积分返回结果

```cpp
/// @brief 积分结算结果 (/point/settle 响应)
struct PointSettleInfo {
    int consumed = 0;           // 本次实际消耗
    int refunded = 0;           // 本次返还
    int total_balance = 0;      // 结算后总积分
    int frozen_points = 0;      // 结算后冻结积分
    int available_points = 0;   // 结算后可用积分
};
```

### 2.3 PointInfoBase — 任务中嵌入的积分元信息

Credit API 的权威字段统一收敛于此，替代 GenJobInfo_s 中旧的 `cost_credits` / `points_balance`。

```cpp
/// @brief 嵌入到各类任务结构体中的积分元信息
///        生成式: 放在 GenJobInfo_s 中 (替代旧的 cost_credits/points_balance)
///        重建式: 放在 JobInfo_s (TaskGraph_s::job) 中
struct PointInfoBase {
    // --- 冻结 (from /point/freeze) ---
    std::string freeze_no;          // 冻结单号
    int frozen_points = 0;          // 冻结积分总额

    // --- 结算 (from /point/settle, points_settled=true 时有效) ---
    int consumed = 0;               // 实际消耗
    int refunded = 0;               // 返还积分
    bool points_settled = false;    // 是否已结算 (崩溃恢复关键字段)

    // --- 余额快照 (freeze/settle 均返回, 以最新一次为准) ---
    int total_balance = 0;          // 总积分
    int available_points = 0;       // 可用积分
};
```

### 2.4 GenJobInfo_s 字段整合

#### 删除旧字段

`GenJobInfo_s` 中删除 `cost_credits` 和 `points_balance`。这两个字段来自 Task API（submit/query）、含义被 Credit API 字段覆盖：

| 旧字段 | 含义 | 被替代为 |
|--------|------|---------|
| `cost_credits` | Task API 返回的消耗估算 | 提交前: Credit `/point/estimate` → `estimate_points`; 结算后: Credit `/point/settle` → `consumed` |
| `points_balance` | Task API 返回的余额 | Credit `/point/freeze` 或 `/point/settle` → `available_points` / `total_balance` |

#### 新增字段

```cpp
// GenJobInfo_s 中:
// --- 积分 (统一由 Credit API 管理, 替代旧 cost_credits/points_balance) ---
PointInfoBase point_info;
```

#### ApplyResponse 修改

`GenJobInfo_s::ApplyResponse()` 不再处理积分字段（`cost_credits` / `points_balance` 已删除）。积分数据的回填由 `ProcessPendingJobs` 和 `ProcessRunningJobs` 中单独调用 FreezePoints / SettlePoints 后写入 `point_info`。

#### GenTaskResponse 修改

`GenTaskResponse` 中删除 `cost_credits` 和 `points_balance` 字段。`GenHttpClient::SubmitTask` / `QueryTaskStatus` 不再解析这两个 JSON key。

### 2.5 重建式：JobInfo_s (在 TaskDef.h) 新增

```cpp
// TaskDef.h 的 JobInfo_s 中增加:
PointInfoBase point_info;           // 积分元信息 (含 freeze_no / points_settled 等)
```

> 重建式同样不使用旧的 `cost_credits` / `points_balance`。

### 2.6 BIN 序列化同步 — 设计原则

**生成式和重建式遵循相同的分层模式**：内存结构体（`GenJobInfo_s` / `JobInfo_s`）嵌 `PointInfoBase`，序列化通过 `WriteToBin` / `LoadFromBin` 落盘。

| 层次 | 生成式 | 重建式 |
|------|--------|--------|
| 内存 | `GenJobInfo_s::point_info` | `JobInfo_s::point_info` |
| 序列化承载 | `GenJobInfoData` (在 `GenJobFile` 内) | `JobInfoData` (在 `JobListFile` 内) |
| 序列化入口 | `GenJobFullInfo_s::WriteToBin/LoadFromBin` | `JobFullInfo_s::WriteToBin/LoadFromBin` |

> **注意**: `GenJobFullInfo_s::WriteToBin` 和 `JobFullInfo_s::WriteToBin` 当前实现是将上层 struct 字段逐字段平铺拷贝到 `GenJobInfoData` / `JobInfoData` 再调用 `Serialize()`。因此 `PointInfoBase` 的新增字段必须同步加到这两个 Data 结构体中，并更新其 `Serialize()` / `Deserialize()` 和初始化代码。详见 [2.7](#27-genjobinfodata--genjobfile-序列化改动) 和 [2.8](#28-jobinfodata--joblistfile-序列化改动)。

### 2.7 GenJobInfoData / GenJobFile — 序列化改动

`DataStruct.h` 中 `GenJobInfoData` 新增 PointInfoBase 扁平字段，`GenJobFullInfo_s::WriteToBin` / `LoadFromBin` 做对应映射。

```cpp
// === GenJobInfoData 新增字段 ===
struct GenJobInfoData
{
    // ... 现有字段不变 (task_uuid ~ query_retry_count) ...

    // --- 积分 (PointInfoBase 扁平) ---
    std::string freeze_no;          // PointInfoBase::freeze_no
    int frozen_points = 0;          // PointInfoBase::frozen_points
    int consumed = 0;               // PointInfoBase::consumed
    int refunded = 0;               // PointInfoBase::refunded
    bool points_settled = false;    // PointInfoBase::points_settled
    int total_balance = 0;          // PointInfoBase::total_balance
    int available_points = 0;       // PointInfoBase::available_points

    // 构造函数中初始化
    GenJobInfoData()
    {
        // ... 现有初始化不变 ...
        freeze_no = "";
        frozen_points = 0;
        consumed = 0;
        refunded = 0;
        points_settled = false;
        total_balance = 0;
        available_points = 0;
    }

    // Serialize 末尾新增 (在 query_retry_count 之后)
    bool Serialize(std::ofstream& out) const
    {
        // ... 现有序列化逻辑 (task_uuid ~ query_retry_count) ...

        unsigned int freeze_no_len = freeze_no.size();
        byteCrypt.WriteByteDecrypted(out, reinterpret_cast<const char*>(&freeze_no_len), sizeof(freeze_no_len));
        byteCrypt.WriteByteDecrypted(out, freeze_no.c_str(), freeze_no_len);

        byteCrypt.WriteByteDecrypted(out, reinterpret_cast<const char*>(&frozen_points), sizeof(int));
        byteCrypt.WriteByteDecrypted(out, reinterpret_cast<const char*>(&consumed), sizeof(int));
        byteCrypt.WriteByteDecrypted(out, reinterpret_cast<const char*>(&refunded), sizeof(int));
        byteCrypt.WriteByteDecrypted(out, reinterpret_cast<const char*>(&points_settled), sizeof(bool));
        byteCrypt.WriteByteDecrypted(out, reinterpret_cast<const char*>(&total_balance), sizeof(int));
        byteCrypt.WriteByteDecrypted(out, reinterpret_cast<const char*>(&available_points), sizeof(int));

        return true;
    }

    // Deserialize 末尾新增 (在 query_retry_count 之后)
    bool Deserialize(std::ifstream& in)
    {
        // ... 现有反序列化逻辑 ...

        unsigned int freeze_no_len = 0;
        byteCrypt.ReadByteDecrypted(in, reinterpret_cast<char*>(&freeze_no_len), sizeof(unsigned int));
        freeze_no.resize(freeze_no_len);
        byteCrypt.ReadByteDecrypted(in, &freeze_no[0], freeze_no_len);

        byteCrypt.ReadByteDecrypted(in, reinterpret_cast<char*>(&frozen_points), sizeof(int));
        byteCrypt.ReadByteDecrypted(in, reinterpret_cast<char*>(&consumed), sizeof(int));
        byteCrypt.ReadByteDecrypted(in, reinterpret_cast<char*>(&refunded), sizeof(int));
        byteCrypt.ReadByteDecrypted(in, reinterpret_cast<char*>(&points_settled), sizeof(bool));
        byteCrypt.ReadByteDecrypted(in, reinterpret_cast<char*>(&total_balance), sizeof(int));
        byteCrypt.ReadByteDecrypted(in, reinterpret_cast<char*>(&available_points), sizeof(int));

        return true;
    }
};
```

> **兼容性**: 新字段全在末尾，默认值为 0/false/空字符串。旧 BIN 文件的 EOF 会使 `ReadByteDecrypted` 返回 false，`data` 不被修改（详见 `ByteCrypt::ReadByteDecrypted` 实现），变量保持构造函数初始值，反序列化安全降级。

```cpp
// === GenJobFullInfo_s::WriteToBin — 新增加点字段映射 ===

    d.frozen_points    = job.point_info.frozen_points;
    d.consumed         = job.point_info.consumed;

    d.points_settled   = job.point_info.points_settled;
    d.total_balance    = job.point_info.total_balance;

}

// === GenJobFullInfo_s::LoadFromBin — 新增加点字段映射 ===
bool LoadFromBin(const std::string& filePath)
{

    // 积分 (GenJobInfoData → PointInfoBase 平铺)
    job.point_info.freeze_no        = d.freeze_no;
    job.point_info.frozen_points    = d.frozen_points;
    job.point_info.consumed         = d.consumed;
    job.point_info.refunded         = d.refunded;
    job.point_info.points_settled   = d.points_settled;
    job.point_info.total_balance    = d.total_balance;
    job.point_info.available_points = d.available_points;

}
```

## 四、PointManager — Core 层积分管理类

### 4.0 设计定位

`PointManager` 是 MoldAIData.dll 中积分系统的**唯一入口**。前端和引擎都链接 MoldAIData.dll，均可直接调用。HTTP 调用细节全部封装为私有静态方法，外部不可见。

```
前端 (MoldAI.exe)                      引擎 (MoldAINode.exe)
    │                                       │
    ├─ PointManager::EstimateTaskPoints()   ├─ PointManager::CreatePointTask()
    ├─ PointManager::QueryUserPoints()      ├─ PointManager::SettlePoints()
    │                                       │
    └───────────────┬───────────────────────┘
                    │
            PointManager (MoldAIData.dll)
              ├─ 公开: EstimateTaskPoints / CreatePointTask / QueryUserPoints / SettlePoints
              └─ 私有: postPointsOutline / postPointsFreeze / postPointsSettle / postPointsEstimate
                    │
                    HttpClient::post()  (复用现有 HTTP 工具类)
```

### 4.2 实现

```cpp
// ==================== Src/Core/PointManager.cpp ====================
#include "Core/PointManager.h"
#include "Util/HttpClient.h"
#include "Util/constant.h"         // SETTINGS_PREFIX / CURRENT_PREFIX / TOKEN_PREFIX
#include "Core/Types.h"            // GEN_SERVER_URL / GEN_API_PREFIX
#include "Core/Logging.h"
#include <QSettings>
#include <QDateTime>
#include <QCryptographicHash>
#include <thread>
#include <chrono>

namespace AI3D {
namespace CORE {

// ============================== 鉴权工具 ==============================

QString PointManager::loadAccessToken()
{
    QSettings settings(SETTINGS_PREFIX + "\\User", QSettings::NativeFormat);
    QString currentUser = settings.value(CURRENT_PREFIX, "").toString();
    if (currentUser.isEmpty())
        return "";
    QString tokenKey = TOKEN_PREFIX + currentUser;
    return settings.value(tokenKey, "").toString();
}

QString PointManager::buildAuthHeader(const QString& url, const QString& dataJson)
{
    QString path = url;
    path.remove(GEN_SERVER_URL);

    QString timestampStr = QString::number(QDateTime::currentDateTime().toSecsSinceEpoch());
    QString accessToken = loadAccessToken();

    QString finalStr = "moldai:" + path + ":" + timestampStr;
    if (!dataJson.isEmpty())
        finalStr += ":" + dataJson;
    if (!accessToken.isEmpty())
        finalStr += ":" + accessToken;

    QByteArray signBase64 = QCryptographicHash::hash(
        finalStr.toUtf8(), QCryptographicHash::Md5).toBase64();

    QString authHeader = "timestamp:" + timestampStr + ",sign:" + signBase64;
    if (!accessToken.isEmpty())
        authHeader += ",accessToken:" + accessToken;

    return authHeader;
}

// =========================== /point/outline ==========================

PointFreezeInfo PointManager::postPointsOutline(int timeout_ms, int max_retries)
{
    QString url = GEN_SERVER_URL + GEN_API_PREFIX + "/point/outline";
    QMap<QString, QString> headers;
    headers["Authorization"] = buildAuthHeader(url, "");

    for (int attempt = 0; attempt <= max_retries; attempt++)
    {
        PointFreezeInfo result;
        bool ok = false;

        HttpClient client(nullptr);
        client.post(url, {}, headers, [&](int, int errorCode, QString, QJsonObject doc)

    "${CMAKE_CURRENT_SOURCE_DIR}/../../include/Util/constant.h"     # ← 新增 (SETTINGS_PREFIX 等宏)

# 2. Sources: 增加 HttpClient.cpp

### 4.4 与 GenHttpClient 的关系

`GenHttpClient` 保持原有职责（Task API：SubmitTask / QueryTaskStatus / CancelTask），**不再包含任何积分相关方法**。原有 `FreezePoints` / `SettlePoints` / `QueryPointsOutline` 从 `GenHttpClient` 中移除，逻辑迁移至 `PointManager` 私有方法中。

| 层 | 职责 |
|----|------|
| `GenHttpClient` (App/Engine) | Task API: submit / query / cancel |
| `PointManager` (Src/Core → MoldAIData.dll) | Credit API: outline / freeze / estimate / settle |

## 五、生成式任务集成

> 积分 API 的 HTTP 调用已迁移至 [第四章 PointManager](#四pointmanager--core-层积分管理类) 私有方法中。
> GenHttpClient 不再包含任何积分方法，专注 Task API (SubmitTask/QueryTaskStatus/CancelTask)。


### 5.0 调用方适配

生成式通过 `GenTaskThread` 调用积分接口。`GenTaskParams::ToJsonString()` 和 `ToString(params.sub_type)` 提供 `task_param_json` 和 `business_type`。

```cpp
// 生成式调用示例:

    ToString(job.params.sub_type),    // business_type: "text-to-model" 等
    job.params.ToJsonString());       // task_param_json

### 5.1 ProcessPendingJobs — Submit 成功后调用 FreezePoints

在原流程中 `SubmitTask` 成功 → 移到 Running 之前，插入冻结积分步骤。

修改位置对应 Checklist Phase 4.1 中 `ProcessPendingJobs` 的第 5 步（提交成功后的处理）：

```cpp
// === ProcessPendingJobs 中 submit 成功后的处理 (修改后) ===

// 5. 提交成功 → 回填 server_task_id → 冻结积分 → 移到 Running
job.ApplyResponse(resp);

// ★ 新增: 冻结积分 (submit 成功后第一要务)
// 失败则不移到 Running, 下轮重试
PointFreezeInfo freezeResult = PointManager::CreatePointTask(
    ToString(job.params.sub_type),
    job.params.ToJsonString());
if (freezeResult.freeze_no.empty())
{
    // 冻结失败 → 不移动文件, 下轮重试
    // 本轮已经 submit 成功有 server_task_id, 下轮 ProcessPendingJobs
    // 的崩溃恢复路径会直接跳过 submit 进入这里重试 FreezePoints
    LOGW("FreezePoints failed for: " + job.task_uuid + ", will retry");
    info.save_with_retry(filePathStr);  // 保存 server_task_id, 下轮跳过 submit
    continue;
}

// 回填冻结结果
job.point_info.freeze_no = freezeResult.freeze_no;
job.point_info.frozen_points = freezeResult.frozen_points;
info.save_with_retry(filePathStr);

// 后续: 注册 Block → UpdateFeedback → 移到 Running (现有逻辑不变)
```

**幂等性**：下一轮扫描时，job 已有 `server_task_id` 但没有 `freeze_no`（崩溃恢复路径中检查 `freeze_info.freeze_no.empty()`），会跳过 submit 直接重试 FreezePoints。

### 5.2 ProcessRunningJobs COMPLETED — 先结算积分再更新状态

这是核心改动。现有代码在 COMPLETED 分支中先 `ApplyResponse` → `save` → `UpdateFeedback` → 更新 Block → `MoveJobFile`。修改后积分结算插入到最前面。

```cpp
case GenTaskStatus::COMPLETED:
{
    // ================================================================
    // ★ 第一步: 积分结算 (必须在任何状态变更之前)
    // ================================================================
    if (!job.point_info.points_settled)
    {
        // 确定结算状态: 根据服务端返回的任务结果决定
        std::string settleStatus = SettleStatus::SUCCESS;  // COMPLETED → success

        // 将 GenTaskParams 序列化为 task_param
        std::string taskParamJson = job.params.ToJsonString();

        PointSettleInfo settleResult = PointManager::SettlePoints(
            job.point_info.freeze_no, settleStatus, taskParamJson);

        // 检查结算是否成功: consumed != 0 或 refunded != 0 表示有效结果
        if (settleResult.consumed == 0 && settleResult.refunded == 0)
        {
            // 结算失败 (网络超时 / 服务端拒绝)
            // → 不更新状态 / 不写结果 / 不移文件
            // → 下轮继续重试
            LOGE("SettlePoints failed for: " + job.task_uuid
                 + " freeze_no=" + job.point_info.freeze_no
                 + ", keeping in Running for retry");
            break;  // ★ 关键: 直接 break, 不做任何状态更新
        }

        // 结算成功 → 回填结果 → 标记已结算 → 落盘
        job.point_info.consumed = settleResult.consumed;
        job.point_info.refunded = settleResult.refunded;
        job.point_info.frozen_points = settleResult.frozen_points;
        job.point_info.total_balance = settleResult.total_balance;
        job.point_info.available_points = settleResult.available_points;
        job.point_info.points_settled = true;
        info.save_with_retry(filePathStr);  // 先持久化 points_settled 标志
        LOGI("SettlePoints OK: " + job.task_uuid
             + " consumed=" + std::to_string(settleResult.consumed)
             + " refunded=" + std::to_string(settleResult.refunded));
    }
    // ================================================================

    // ★ 第二步: 走到这里说明积分已结算 (正常或崩溃恢复)
    //     按现有逻辑更新状态/结果/feedback/Block/移文件
    job.ApplyResponse(resp);
    info.save_with_retry(filePathStr);
    UpdateFeedback(info);
    info.feedback.save_with_retry(fbPath, false);

    // 更新 Block 中的状态和 result_url (现有逻辑)
    {
        std::string blkPath = job.project_path + "/" + job.block_item + ".blk";
        BlockObject::Task_Info blkInfo;
        if (blkInfo.ReadBlockInfoBin(blkPath))
        {
            for (auto& gen : blkInfo.generations_info_)
            {
                if (gen.task_uuid == job.task_uuid)
                {
                    gen.status = static_cast<int>(GenTaskStatus::COMPLETED);
                    if (!job.result_url.empty())  gen.result_url  = job.result_url;
                    if (!job.preview_url.empty()) gen.preview_url = job.preview_url;
                    break;
                }
            }
            blkInfo.WriteBlockInfoToBin(blkPath, false);
        }
    }
    MoveJobFile(filePathStr, qstr2str(genCompletedJobPath));
    LOGI("Completed: " + job.task_uuid);
    break;
}

## 六、重建式任务集成

### 6.0 调度模型差异

```
生成式: GenTaskThread → HTTP submit → HTTP query → HTTP settle
重建式: Engine spawn Task.exe → Task 写 feedback → Engine 读 feedback 终态
```

重建式没有 HTTP 轮询。积分结算发生在 **Engine 检测到反馈文件中的终态（COMPLETE/FAILED/CANCELED）之后**。

调用链：
```
searchPendingJobThread2 / searchRunningJobThread2
  → TaskGraph_s 的 JobFeedBack_s 检测到终态
  → PointManager::SettlePoints(freeze_no, status, task_param_json)
    ├─ 成功 → 更新状态 / 移到 Finished 目录
    └─ 失败 → 保持 Running，下轮重试
```

### 6.1 重建式冻结积分点

重建式任务由 Engine 创建 Task.exe 子进程之前冻结积分。对应位置：`CallEngine.cpp` 中 `ExecTaskFileV2()` 函数，在 `QProcess::start()` 之前。

```cpp
// === CallEngine.cpp: ExecTaskFileV2() / 类似创建 Task 的位置 ===

// 1. 构造 task_param (根据 TaskGraph_s 中的任务信息)
//    重建式 task_param 格式与估算接口一致:
//    { "images": { "total_count": N }, "tiles": { "total_count": M } }
std::string taskParamJson = BuildReconstructionTaskParam(tg);

// 2. 冻结积分
PointFreezeInfo freezeResult = PointManager::CreatePointTask(
    GetBusinessType(tg.job.JobType),   // jobtype_e → business_type 字符串
    taskParamJson);

if (freezeResult.freeze_no.empty())
{
    // 冻结失败 → 不启动 Task.exe → 标记 Job FAILED
    LOGE("FreezePoints failed, aborting job");
    tg.job.Status = STATUS_FAILURE;
    // ... 写 feedback 等 ...
    return;
}

// 3. 回填 freeze_no → 落盘
tg.job.freeze_no = freezeResult.freeze_no;
JobFullInfo_s::Save(jobfile);  // 或 WriteToBin

// 4. 启动 Task.exe (现有逻辑)
QProcess::start("MoldAITask.exe", {taskfile});
```

### 6.2 重建式结算积分点

在现有 `searchRunningJobThread2` 或类似的 job 状态检查逻辑中，检测到终态后**先 settle 再移动文件**。

```cpp
// === CallEngine.cpp: searchRunningJobThread2 / 状态检测循环 ===

// 检测到 JobFeedBack_s 为终态 (COMPLETE / FAILED / CANCELLED)
if (fb.Status == STATUS_COMPLETE || fb.Status == STATUS_FAILED || fb.Status == STATUS_CANCELED)
{
    JobInfo_s& job = tg.job;

    // ★ 积分结算 (先于任何状态变更)
    if (!job.points_settled && !job.freeze_no.empty())
    {
        std::string settleStatus;
        if (fb.Status == STATUS_COMPLETE)       settleStatus = "success";
        else if (fb.Status == STATUS_FAILED)    settleStatus = "fail";
        else if (fb.Status == STATUS_CANCELED)  settleStatus = "cancel";

        std::string taskParamJson = BuildReconstructionTaskParam(tg);

        PointSettleInfo settleResult = PointManager::SettlePoints(
            job.freeze_no, settleStatus, taskParamJson);

        if (settleResult.consumed == 0 && settleResult.refunded == 0)
        {
            // 结算失败 → 保持 Running 状态，下轮重试
            LOGE("SettlePoints failed for job, retry next cycle");
            continue;
        }

        job.point_info.consumed = settleResult.consumed;
        job.point_info.refunded = settleResult.refunded;
        job.point_info.frozen_points = settleResult.frozen_points;
        job.point_info.total_balance = settleResult.total_balance;
        job.point_info.available_points = settleResult.available_points;
        job.point_info.points_settled = true;
        JobFullInfo_s::Save(jobfile);
        LOGI("SettlePoints OK: consumed=" + std::to_string(settleResult.consumed));
    }
    // 只有 points_settled 后才执行终态文件移动
    MoveJobToFinished(jobfile, fb.Status);
}
```

/// @brief 构造重建式任务参数 JSON (对齐 /point/freeze, /point/settle, /point/estimate 的 task_param 格式)
///        顶层结构: { "images": { "total_count": N }, "tiles": { "total_count": M } }
inline std::string BuildReconstructionTaskParam(const TaskGraph_s& tg)
{
    // 从 TaskGraph_s 的 tasksmap 中累计 photo_count 和 tile_count
    int imageCount = 0;
    int tileCount = 0;
    for (const auto& kv : tg.tasksmap)
    {
        const ATTaskDef_s& task = kv.second;
        imageCount += task.photo_count;
        if (task.Type == TILETASKTYPE)
        {
            // 每个 tile 任务对应一个 tile 块
            tileCount++;
        }
    }

    rapidjson::Document doc;
    doc.SetObject();
    auto& alloc = doc.GetAllocator();

    rapidjson::Value images(rapidjson::kObjectType);
    images.AddMember("total_count", imageCount, alloc);
    doc.AddMember("images", images, alloc);

    rapidjson::Value tiles(rapidjson::kObjectType);
    tiles.AddMember("total_count", tileCount, alloc);
    doc.AddMember("tiles", tiles, alloc);

    rapidjson::StringBuffer buffer;
    rapidjson::Writer<rapidjson::StringBuffer> writer(buffer);
    doc.Accept(writer);
    return buffer.GetString();
}
```

## 七、崩溃恢复分析

### 7.1 各崩溃点的恢复路径

| 崩溃时机 | job 状态 | 重启后行为 |
|----------|----------|-----------|
| SubmitTask 成功，FreezePoints 前崩溃 | Running/, server_task_id 有, freeze_no 空 | ProcessPendingJobs 崩溃恢复路径: 检测到 server_task_id 非空 → 直接移回 Running。下一轮 ProcessRunningJobs 扫描时 server_task_id 有但 freeze_no 空 → **需兜底** (见 7.2) |
| FreezePoints 成功，移到 Running 前崩溃 | Pending/, server_task_id 有, freeze_no 有 | ProcessPendingJobs: server_task_id 非空 → 移回 Running (崩溃恢复) |
| SettlePoints 成功，points_settled 落盘后崩溃 | Running/, points_settled=true | ProcessRunningJobs COMPLETED: points_settled=true → 跳过 settle → 正常完成流程 |
| SettlePoints 成功，points_settled 落盘前崩溃 | Running/, points_settled=false | ProcessRunningJobs COMPLETED: points_settled=false → 重试 settle。服务端应保证 settle 幂等 |
| 状态更新中崩溃 | Completed/ 或 Running/ | 已在 Completed/ 则无事; 在 Running/ 则下轮继续 |

### 7.2 关键兜底: freeze_no 为空的 Running 任务

如果 Running/ 中的任务有 `server_task_id` 但没有 `freeze_no`，说明 FreezePoints 从未成功。需要在 `ProcessRunningJobs` 开头增加兜底：

```cpp
// ProcessRunningJobs 中, server_task_id 检查之后, QueryTaskStatus 之前

// ★ 兜底: server_task_id 已有但 freeze_no 为空 → 补调 FreezePoints
if (job.point_info.freeze_no.empty())
{
    LOGW("Running job missing freeze_no, retrying FreezePoints: " + job.task_uuid);
    PointFreezeInfo freezeResult = PointManager::CreatePointTask(
        ToString(job.params.sub_type),
        job.params.ToJsonString());
    if (freezeResult.freeze_no.empty())
    {
        // 仍然失败, 下轮重试 (不查状态, 不更新)
        LOGE("FreezePoints still failed for: " + job.task_uuid);
        continue;
    }
    job.point_info.freeze_no = freezeResult.freeze_no;
    job.point_info.frozen_points = freezeResult.frozen_points;
    info.save_with_retry(filePathStr);
    LOGI("FreezePoints retry OK: " + job.task_uuid + " freeze_no=" + job.point_info.freeze_no);
}
```

### 7.3 服务端 settle 幂等性要求

**必须与服务端约定: 相同 `freeze_no` 的重复 settle 请求返回相同结果 (幂等)。**

如果服务端不保证幂等，崩溃恢复时重复 settle 可能导致重复扣费。这是上线前置条件。

## 十三、测试要点

1. **正常流程 (生成式)**: submit → freeze → running → query(COMPLETED) → settle → completed
2. **正常流程 (重建式)**: spawn 前 freeze → Task 执行 → 检测终态 → settle → 移目录
3. **freeze 失败**: submit/spawn 成功但 freeze 超时 → 不进入 Running → 下轮重试 freeze
4. **settle 失败**: 任务 COMPLETED 但 settle 超时 → 保持在 Running/ → 下轮重试 settle
5. **settle 幂等**: 模拟 settle 成功后 crash → 重启后 points_settled=true → 跳过 settle → 正常完成
6. **freeze 兜底**: 手动构造 Running/ 中无 freeze_no 的 job → 补 FreezePoints
7. **不同终态的 settle**: COMPLETED→"success", FAILED→"fail", CANCELLED→"cancel"
